# M23 Release B — next default and legacy retirement

Release B promoted `next` to the normal battle entry. Ticket 19 retires the
temporary legacy entry after the release evidence and owner instruction were
reviewed. The current app has one full scene renderer and one-way fallback to
the DOM compatibility renderer. Renderer selection is display-only and never
enters a save, replay, or player preference.

## Retirement record

- Release A evidence remains under the ignored `test-runs/m23/release-a-*`
  directories and in [`m23-release-a.md`](./m23-release-a.md).
- Release B next, compatibility, artwork, and injected failure journeys were
  run with seed `m23-current-parity-v1-seed`, digest `5621dba2`, all nine
  checkpoints, and zero browser errors. Their evidence remains under the
  ignored `test-runs/m23/release-b-*` directories.
- The owner authorized the Ticket 19 retirement implementation on 2026-09-08.
  This repository has no production telemetry or release-calendar authority;
  the elapsed one-release stability observation is therefore an external
  release-management record rather than a claim generated by the app.

## Route policy

- An absent route enters `next` in production and ordinary development.
- `compatibility` is the only alternate entry and is used for WebGL,
  shader, chunk, context, and sustained-performance failures. It remains
  playable and latches for the current session.
- The old `renderer=legacy` and `rendererRoute=legacy` query values are ignored
  by the current app and consequently resolve to the `next` default. They no
  longer load a legacy chunk or expose a player-facing choice.
- The DEV M23 driver and CDP harness may request `next` or `compatibility`
  explicitly for evidence.

Both entries consume the same `BattleSceneSnapshot`, session token,
presentation coordinator, seeded battle flow, replay recorder, and result
handoff. A renderer switch does not rerun the reducer, input, canonical commit,
or result handoff.

## Evidence commands

With the existing Vite and Chrome/CDP setup from `README.md`, run the default
route and then the compatibility route:

```sh
node scripts/m23-baseline.mjs --seed=m23-current-parity-v1-seed --device=release-b-next-retired
node scripts/m23-baseline.mjs --renderer=compatibility --seed=m23-current-parity-v1-seed --device=release-b-compatibility-retired
node scripts/m23-baseline.mjs --renderer=next --artwork=large-texture --seed=m23-current-parity-v1-seed --device=release-b-artwork-success-retired
node scripts/m23-baseline.mjs --renderer=next --artwork=artwork-404 --seed=m23-current-parity-v1-seed --device=release-b-artwork-failure-retired
node scripts/m23-baseline.mjs --renderer=next --rendererFailure=chunk-reject --seed=m23-current-parity-v1-seed --device=release-b-chunk-reject-retired
node scripts/m23-baseline.mjs --renderer=next --rendererFailure=webgl-unsupported --seed=m23-current-parity-v1-seed --device=release-b-webgl-retired
node scripts/m23-baseline.mjs --renderer=next --rendererFailure=shader-error --seed=m23-current-parity-v1-seed --device=release-b-shader-retired
node scripts/m23-baseline.mjs --renderer=next --rendererFailure=context-lost --seed=m23-current-parity-v1-seed --device=release-b-context-retired
npm run perf:check -- --renderer=next --evidence=true --device=release-b-next-retired
```

The harness rejects `--renderer=legacy`; this is an intentional check that the
retired route cannot be reintroduced through the evidence path. A stale URL
containing `renderer=legacy` can still be opened to verify it lands on `next`.

The default, compatibility, artwork, and injected-failure journeys must record
the requested route, effective route, seed, digest, fallback reason, browser
errors, and final result. Artwork success must report `artwork/artwork`; a
failed artwork fixture must report `silhouette/artwork`. SwiftShader is useful
for functional evidence only and cannot support a performance verdict.

## Rollback history and failure behavior

1. Release A rollback evidence is preserved in `docs/m23-release-a.md` and its
   ignored evidence directories.
2. Release B's temporary legacy route is preserved in the historical
   `release-b-legacy-rollback` evidence directory and commit history.
3. The current release rolls forward through the automatic compatibility path
   when `next` cannot boot or render. It does not retry the canonical turn.
4. To restore the previous full renderer, deploy the previous release artifact;
   the current app intentionally has no second full-scene route.

## Known limitations

- Physical iPad Safari landscape/portrait, safe area, touch, 200% zoom,
  thermal, and Safari performance evidence from Ticket 16 remains an external
  qualification step.
- The full five-viewport, retained-heap, long artwork-churn, and five-minute
  thermal matrix is release evidence work beyond the short local journeys.
- The app has no uploaded telemetry, so natural production fallback rates are
  unavailable. Injected failure counts only prove the designed fallback path.
